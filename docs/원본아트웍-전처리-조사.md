# 원본 아트웍 전처리 조사 — 설명 그래픽·숫자 규격 제거

> 작성 2026-08-31. 요청: "원본 아트웍을 설명하는 그래픽 요소와 숫자 규격을
> 지우는 기능"의 실현 방안 조사. 결론은 **안 C(사용자 지정 제외 영역) 우선,
> 안 B(자동 후보 제안)로 보조** — 자동 '삭제'는 검수 도구 특성상 위험해서
> 사람이 확정하는 구조를 권장한다.

## 1. 문제 정의

원본 아트웍(REF)에는 실물 인쇄물에는 없는 요소가 들어 있을 수 있다:

- 재단선(트림 마크)·레지스터 마크(⊕)·컬러바 — 인쇄 공정용
- 치수선·치수 숫자(mm), 규격 표(숫자 규격) — 아트웍을 설명하는 정보
- 문서번호/개정 표기, 승인란, 주석 텍스트 — 관리 정보

이 요소들은 TEST(실물 스캔)에 없으므로 그대로 비교하면 **"인쇄 누락(missing,
critical)" 오탐**이 된다.

## 2. 현재 상태 실측 (2026-08-31)

- 엔진은 REF 사방 **6% 마진 밴드**(`marginRatio 0.06`, `in_margin` —
  compare_artwork.py:552, engine.ts의 동일 포트)에 **완전히 들어간** 검출을
  버린다. 실측(pga1e0398 REF, 5564×7100): 레지스터 마크 4개(101×101px,
  가장자리)와 재단선 조각(125×3px) **전부가 6% 밴드 안** → 현 파이프라인이
  이미 무시한다. README의 "재단선/레지스터 마크 부재는 보고하지 않음"이 이
  메커니즘이다.
- 이 REF는 완전 그레이스케일이었다(채도 픽셀 0개) — "빨간 재단선" 같은
  컬러 주석은 이 샘플에는 없음.
- 저장소의 벤치 케이스에는 **치수선·규격 표가 콘텐츠 영역 안쪽에 있는 원판
  샘플이 없다.** 즉 남는 문제는 "6% 밴드 밖(=콘텐츠 영역)에 설명 요소가 있는
  원판"인데, 실물 샘플 확보가 선행돼야 한다(§6).

## 3. 접근안 비교

### 안 A — PDF 레이어(OCG) 필터링 (원판이 레이어 분리된 경우만)
디자인 원판 PDF는 재단선/치수/주석을 별도 레이어(Optional Content Group)에
두는 경우가 많다. pdf.js(현재 `pdfjs-dist@6`)는
`getOptionalContentConfig()`로 레이어 목록을 얻고, 렌더 시
`optionalContentConfigPromise`로 특정 레이어를 끈 채 래스터화할 수 있다 —
삽입 지점은 `web/src/pipeline/pdf.ts`의 `renderPage()`(page.render 옵션 한
개 추가). UI는 "PDF 레이어 선택" 체크리스트.
- 장점: 벡터 단계에서 완전 제거(찌꺼기 없음), 결정론적.
- 한계: **원판이 실제로 레이어를 나눠놨을 때만** 동작. 납품용으로 평탄화된
  PDF(레이어 1개)면 무력. 별색(CutContour 등) 기반 분리는 pdf.js가 렌더 전에
  대체 색공간으로 병합해버려 사실상 불가.
- 판단: 실제 원판 PDF 확보 후 레이어 유무를 보고 결정(§6). 있다면 구현은
  하루 이내 소규모.

### 안 B — 래스터 휴리스틱 자동 검출(자동 '제거'는 비권장)
결정론(OpenCV)으로 후보를 찾을 수 있는 것들:
- 컬러 주석: 라벨 인쇄가 흑백/단색일 때 채도 높은 픽셀(|R−G|+|R−B|+|G−B| >
  임계) — 재단선 빨강, 치수선 파랑 등.
- 레지스터 마크: 마진 밴드 부근의 고립된 소형 원+십자 성분(이번 실측 101×101).
- 규격 숫자·치수선: 콘텐츠 본문에서 뚝 떨어진 고립 성분 + OCR로 "숫자+mm"
  패턴 확인.
- 문제: **자동으로 지우면 실결함 은폐 위험**이 생긴다. 의료기기 라벨 검수
  도구에서 "도구가 몰래 지운 영역"은 감사 관점에서도 나쁘다. → 자동은
  **후보 사각형 제안까지만** 하고 확정은 사람이 한다(안 C의 입력 보조).

### 안 C — 사용자 지정 제외 영역 (권장, 1차 구현 대상)
REF 위에 사각형을 그려 "검수 제외 영역"으로 지정·저장한다.
- 저장: 공용 보관함 매니페스트 v3에 얹는다 — `ArtworkMeta`에
  `maskRects?: [x,y,w,h][]` 필드 추가(파일 해시에 귀속, **팀 전체에 자동
  전파** — 한 명이 지정하면 끝). v3 병합 규칙(updatedAt 승부)을 그대로 탄다.
- 적용(패리티 무관 — 엔진 수정 없음):
  1. 분석 직전 runner에서 REF ImageData의 해당 영역을 **흰색으로 채운다**
     (missing 오탐 원천 차단). TEST는 건드리지 않는다 — 그 자리에 뭔가
     찍혀 있으면 extra(오염)로 잡히는 게 맞다.
  2. 오버레이에 제외 영역을 회색 빗금으로 표시하고 결과 요약에 "제외 영역
     N개"를 남긴다(은폐가 아니라 명시적 제외임을 리포트에 기록).
- UI: 보관함 항목에 "제외 영역 편집" — 기존 OverlayInspector(확대경) 위에
  드래그로 사각형 추가/삭제. PDF 원본은 1페이지 600dpi 래스터 좌표 기준.
- 장점: 어떤 형태의 설명 요소든(레이어 유무 무관) 동작, 결정론, 감사 가능.
- 단점: 최초 1회 사람 손이 간다(아트웍당 수십 초) — 안 B 후보 제안으로 단축.

## 4. 권장 로드맵

1. **안 C 구현**(1~2일): maskRects 저장(매니페스트 v3 확장) + runner 전처리
   (흰색 채움) + 마스크 편집 UI + 오버레이 표시. 엔진·파리티 무영향.
2. **안 B 후보 제안**(반나절): 컬러 주석·고립 성분 휴리스틱으로 "제외 영역
   후보"를 그려주고 사용자가 확정만.
3. **안 A**는 실제 원판 PDF의 레이어 구조 확인 후 결정.

## 5. 주의(왜 자동 삭제를 안 하나)

- 지운 영역 안의 실결함은 못 잡는다 — 제외는 명시적·가시적이어야 하고,
  리포트에 남아야 한다.
- 6% 마진 밴드가 이미 가장자리 마크를 처리하므로, 마스킹 대상은 "콘텐츠
  영역 안의 설명 요소"로 한정하는 게 오탐/은폐 균형에 맞다.

## 6. 다음에 필요한 것 (조사 미결)

- **설명 그래픽·숫자 규격이 실제로 들어 있는 원판 아트웍 PDF 1~2개** —
  (1) 레이어 분리 여부(안 A 실효성), (2) 요소의 위치·색(안 B 휴리스틱
  임계값), (3) 안 C 편집 UI의 실사용 흐름 확인용. 파일을 보관함에 넣어두면
  이 문서 기준으로 바로 검증할 수 있다.
