인쇄 검수 도구 사용 · 유지보수 안내

02 계정

아이디·비밀번호는 별도 시트로 전달됩니다. 이 페이지에는 적지 않습니다.

  • GitHub — 코드와 자동 배포 설정 (isenswonju/print-compare)
  • Hugging Face — 검수 앱이 배포되는 곳 (print-compare)
  • Vercel — 피드백과 원본 보관함 서버 (i-sens 팀)
  • Tailscale — 사내망 주소를 여는 프로그램 (맥미니)
  • 맥미니 로그인 — 사내망 주소가 필요할 때만 사용
  • ChatGPT — Codex 로그인에 사용

이 페이지에 비밀번호를 적지 마세요

  1. 이 안내서는 검수 앱과 같은 주소에 올라가 있고, 그 주소는 로그인 없이 누구나 열 수 있습니다. 여기에 적으면 인터넷에 공개하는 것과 같습니다.
  2. 비밀번호는 전달받은 계정 시트(사내 공유 폴더 또는 NAS)에만 두고, 이 페이지에는 "어디에 있는지"만 적어 두세요.

03 처음 한 번: 설치

전달받은 압축 파일을 푼 다음, 아래 순서대로 하면 됩니다. Windows 기준입니다.

  1. 압축 풀기

    전달받은 압축 파일을 경로에 한글이나 띄어쓰기가 없는 폴더에 푸세요. 예: C:\print-compare

    바탕화면이나 다운로드 폴더에 그냥 풀면 일부 도구가 경로를 못 찾는 경우가 있습니다.

  2. 설치.bat 더블클릭

    압축을 푼 폴더 안에 설치.bat 이 있습니다. 더블클릭하면 검은 창이 뜨고 필요한 프로그램(Node.js, Python, Codex, 라이브러리)을 알아서 설치합니다. 처음에는 10~20분 걸립니다.

    중간에 파란 경고 창("Windows의 PC 보호")이 뜨면 추가 정보 → 실행을 누르세요. 사내에서 만든 파일이라 서명이 없어서 나오는 안내입니다.

    창 마지막에 [완료] 목록만 있으면 성공입니다. [필요] 가 있으면 거기 적힌 대로 처리한 뒤 설치.bat 을 한 번 더 실행하면 됩니다. 여러 번 실행해도 안전합니다.

  3. Codex 로그인

    설치가 끝난 창에 아래를 치고 엔터를 누르세요. 한 번만 하면 됩니다.

    브라우저가 열리면 ChatGPT 계정으로 로그인
    codex login

    담당자 각자의 개인 ChatGPT/Codex 계정을 사용해도 됩니다. 프로젝트 규칙은 저장소의 AGENTS.md, 배포 권한은 GitHub Actions Secret에 있으므로 Codex 계정이 바뀌어도 유지보수 절차와 배포 결과는 달라지지 않습니다.

  4. GitHub 로그인

    github.com/login을 열어 회사 계정으로 로그인한 뒤 isenswonju/print-compare 저장소가 보이는지 확인하세요.

    처음 Git 작업에서 인증 창이 뜨면 브라우저로 로그인을 선택합니다. GitHub 비밀번호를 명령창에 직접 입력하지 않습니다.

  5. 시작.bat 으로 열기

    앞으로는 폴더 안의 시작.bat 을 더블클릭하면 됩니다. 대화창이 열리면 준비 완료입니다. 첫 시험 삼아 아래를 그대로 붙여넣어 보세요.

    이 프로젝트가 무엇을 하는 도구인지, 최근에 무엇이 바뀌었는지 비개발자가 이해할 수 있게 설명해줘.

규칙은 이미 들어 있습니다. 폴더 안의 AGENTS.md 파일에 "이건 절대 하지 마라", "고친 뒤엔 이 검사를 돌려라" 같은 규칙이 적혀 있고, Codex 가 대화를 시작할 때 자동으로 읽습니다. 매번 설명하지 않아도 됩니다.

04 유지보수하는 법

코드를 고치는 일이 아니라, 무엇을 원하는지 말하는 일입니다.

1
겁나면 "설명만 해줘"로 시작합니다 바로 고치라고 하지 말고 "어떻게 고칠 건지 먼저 설명만 해줘. 아직 고치지 마." 라고 하면 계획만 보여줍니다. 읽고 납득되면 그때 "그대로 해줘".
2
"고쳐줘" 뒤에 "검사도 돌려줘"를 붙입니다 이 프로젝트에는 실수를 잡아내는 자동 검사가 있습니다. "고친 뒤에 테스트와 bench 검사를 돌리고 결과를 보여줘." 결과가 PASS 여야 안심할 수 있습니다.
3
배포는 자동입니다 변경이 회사 GitHub의 main에 반영되면 검사를 모두 통과한 뒤 현장 앱까지 자동 배포됩니다. 운영자가 별도 배포 명령을 외울 필요가 없습니다.

상황별로 그대로 붙여넣을 문장

이럴 때이렇게 말합니다
사용자 피드백을 처리하고 싶다 미확인 피드백 목록을 보여주고, 지적된 내용을 조사해서 원인을 설명해줘. 고칠 수 있으면 고치고, 검사와 배포까지 한 다음 피드백 상태를 확인으로 바꿔줘.
결함이 아닌 걸 결함이라 한다 (오탐) 앱 피드백에서 오탐으로 지목된 최근 건들을 확인하고 원인을 찾아서 고쳐줘. 고친 뒤 테스트와 bench 검사를 돌리고 결과를 보여줘.
진짜 결함을 못 잡는다 (미검출) 이 아트웍 쌍에서 ○○ 부분의 결함을 못 잡는다. 원인을 조사하고 bench 케이스로 등록해줘. 임계값을 바꿔야 한다면 근거 수치를 같이 보여줘.
화면 문구·버튼을 바꾸고 싶다 앱 화면의 '○○○' 문구를 '×××'로 바꿔줘.
고친 걸 현장에 반영하고 싶다 GitHub Actions의 최근 자동 배포가 성공했는지 확인해줘.
지금 상태가 정상인지 보고 싶다 테스트와 bench 검사를 전부 돌려서 지금 상태가 정상인지 확인해줘.
뭐가 바뀌었는지 모르겠다 최근 커밋 10개를 비개발자가 이해할 수 있게 한 줄씩 설명해줘.
승인 창이 뜨면. Codex 는 파일을 고치거나 명령을 실행하기 전에 물어봅니다. 무엇을 하려는지 한 줄로 보여주니 읽고 승인하면 됩니다. 파일 삭제가 보이면 한 번 더 생각하고, 애매하면 거절한 뒤 "왜 그게 필요한지 설명해줘"라고 물어보세요.

05 피드백 처리

현장 의견이 정확도를 고치는 유일한 근거입니다. 처리 상태는 앱과 자동으로 맞춰집니다.

피드백 페이지는 앱 상단의 💬 단추로 열립니다. 비밀번호가 없습니다 — 팀 누구나 열어 현장 의견과 처리 상태를 볼 수 있습니다.

검수 결과에서 잘못 잡은 항목이 보이면, 사용자가 앱에서 '미확인'을 눌러 이유를 남깁니다. 이 의견이 피드백 페이지에 쌓이고, 정확도 개선은 전적으로 이 데이터를 근거로 진행합니다. "요즘 좀 이상하다"는 말만으로는 고칠 수 없으니 현장에 이 버튼을 꼭 안내해 주세요.

대화로 피드백을 처리하면 앱의 피드백 페이지 상태도 함께 바뀝니다. Codex 가 반영을 마친 뒤 해당 건을 '확인'으로 표시하도록 되어 있어, 다른 사람이 같은 건을 다시 조사하는 일이 없습니다. 손으로 앱에서 누르는 확인/미확인 토글과 같은 기록을 씁니다.

단계일어나는 일
1. 접수현장에서 '미확인'을 누르면 피드백 페이지에 미확인으로 쌓입니다.
2. 조사대화로 원인을 묻습니다. 지적 사유와 코멘트를 Codex 가 읽고 설명합니다.
3. 반영고칠 수 있으면 고치고, 자동 검사를 통과시킨 뒤 배포합니다.
4. 마감해당 건이 확인으로 바뀝니다. 앱 피드백 페이지에 바로 보입니다.
고치지 않기로 한 건도 닫습니다. 기술적으로 잡을 수 없는 결함이 있습니다 (아주 가는 획의 끊김 등). 이런 건은 이유를 설명받고 납득한 뒤 '확인'으로 닫으면 됩니다. 열어 두면 계속 다시 조사하게 됩니다.

06 저절로 돌아가는 것들

평소엔 손댈 필요가 없습니다. 문제가 있을 때만 알림이 뜹니다.

언제무엇이 일어나나
GitHub에 변경을 올릴 때전체 안전 검사를 통과한 변경만 현장 앱에 자동 배포됩니다.
코드를 저장할 때마다검사 엔진을 건드린 변경이면 오탐 감시 검사가 30초간 자동으로 돕니다. 깨지면 저장이 막힙니다.
사용자가 피드백을 남길 때'미확인' 표시가 서버에 쌓입니다. 정확도를 개선하는 유일한 근거 데이터입니다.
맥미니 재부팅사내망 서버와 공유 주소가 자동으로 다시 켜집니다.

07 하면 안 되는 것

전부 실제로 사고가 났던 항목입니다. Codex 에게도 같은 규칙이 걸려 있습니다.

이 네 가지는 Codex 가 하겠다고 해도 막으세요

  1. 검사 결과가 FAIL 인데 그냥 넘어가기. 자동 검사가 막았다는 건 잘 되던 게 깨졌다는 뜻입니다. 원인을 고친 뒤에 진행하세요.
  2. 기준선을 확인 없이 승인하기. "기준선을 갱신할까요"라고 물으면, 결과를 눈으로 확인하기 전엔 승인하지 마세요. 승인해 버리면 오류가 새 정답이 됩니다.
  3. 실물 라벨 이미지를 저장소에 올리기. 의료기기 데이터입니다. 이미지 파일을 커밋하려 하면 거절하세요.
  4. 고쳐 놓고 배포를 빠뜨리기. 현장은 계속 옛날 버전을 씁니다. 실제로 이 때문에 오탐 45건이 다시 올라온 적이 있습니다.

08 문제가 생겼을 때

대부분 아래 표에서 끝납니다. 안 되면 증상을 그대로 대화창에 말하세요.

증상조치
앱이 안 열린다 검수 앱 주소를 먼저 시도합니다. 이건 맥미니와 무관하게 열려야 정상입니다. 사내망 주소만 안 열리면 맥미니가 꺼졌거나 잠든 것입니다.
배포했는데 화면이 그대로다 브라우저에서 Ctrl+Shift+R 로 강제 새로고침. 그래도 그대로면 "배포 지문을 확인해줘" 라고 하세요.
검수 결과가 이상하다 앱에서 '미확인'을 눌러 근거를 남긴 뒤, 04번 표의 첫 줄 문장을 붙여넣으세요.
대화가 엉뚱한 답을 한다 대화가 길어지면 흐려집니다. 창을 닫고 시작.bat 으로 새로 시작한 뒤, 원하는 것을 더 구체적으로 한 문장으로 말하세요.
파일을 못 찾는다고 한다 프로젝트 폴더 밖에서 열린 것입니다. 창을 닫고 시작.bat 으로 다시 여세요.
망친 것 같다 / 되돌리고 싶다 저장(커밋) 전이라면 "방금 바꾼 것을 전부 되돌려줘". 저장까지 했다면 "마지막 커밋을 되돌려줘". 배포 전이면 현장에는 아무 영향이 없습니다.

09 백업

NAS 에 두는 방법과, 두면 안 되는 것.

NAS 는 보관용으로만 쓰세요. NAS 폴더에서 직접 작업하면 빌드가 몇 배로 느려지고, 파일 변경 감지와 저장 이력 기능이 자주 깨집니다. 작업은 항상 컴퓨터 내장 디스크(C:\print-compare 같은 곳)에서 하고, 주기적으로 폴더째 압축해 NAS 에 올려 두는 방식이 안전합니다.

백업할 때 빼도 되는 폴더입니다. 용량 대부분을 차지하고, 언제든 다시 만들어집니다.

압축에서 제외해도 되는 폴더
web\node_modules      web\dist
bench\work            bench\out

NAS 에 올릴 때 확인할 것

  1. 공유 범위. 백업본에는 실물 라벨 이미지(의료기기 데이터)와 피드백이 들어 있습니다. 아무나 열 수 있는 공유 폴더에 두지 마세요.
  2. 계정 시트는 따로. 비밀번호 시트는 백업본 안이 아니라, 접근이 통제된 별도 위치에 두세요.

10 용어

대화창이 이 단어들을 씁니다. 뜻만 알면 훨씬 편합니다.

REF / TESTREF 는 승인된 원본 아트웍, TEST 는 실제로 인쇄해 스캔한 것. 이 둘을 겹쳐 비교합니다.
오탐결함이 아닌 것을 결함이라고 잘못 잡은 것.
미검출진짜 결함인데 못 잡은 것. 오탐보다 위험합니다.
